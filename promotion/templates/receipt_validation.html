Этап 2 — Три ветвления валидации товаров

Все три ветвления запускаются независимо. Keywords и RapidFuzz активны всегда; AI — отключён по умолчанию (ai_mode=False). Исключение в одном ветвлении не прерывает остальные.
① Keywords — точное совпадение
Для каждого товара в чеке:
1. Проверить исключающие ключевые слова (excluding_keywords) — если найдено, товар пропускается.
2. Проверить имя продукта из БД (product.name) — подстрочный поиск в названии товара.
3. Проверить ключевые слова продукта (keywords) — подстрочный поиск.
Если продукт найден → проверить глобальное ключевое слово (item_matches_global_keyword).
Если оба условия выполнены → matched=True, ранний выход.
② RapidFuzz — нечёткое совпадение
Для каждого товара строит комбинации «бренд + ключевое слово» из БД и сравнивает с названием товара через:
• WRatio ≥ 65
• partial_ratio ≥ 55
Только если оба порога выполнены — совпадение.
Дополнительный фильтр: название найденного продукта должно состоять более чем из одного слова.
③ AI (Gemini 2.5 Flash) — семантический анализ
Отключён по умолчанию. При включении:
Отправляет все товары чека + список акционных товаров + ключевые слова в OpenRouter (Gemini 2.5 Flash).
AI проверяет совпадение бренда И продукта одновременно.
Возвращает {"matches": true/false}.
Не возвращает конкретные позиции товаров.

Риски

# Серьёз. Проблема Пример
1 Высокий Исключающие ключевые слова проверяются до ключевых слов бренда. Если название продукта акции содержит исключающее слово — он будет пропущен, даже если это акционный товар. Продукт с excluding_keyword «перепелиные» при названии «Яйцо Атемарское Отборное» — товар пропустится.
2 Высокий ФНС обрезает названия товаров до 64 символов. Ключевое слово может быть обрезано в середине. Яйцо куриное Атемарская Ферма отборн — «отборное» обрезано, если оно было ключевым словом.
3 Высокий Все ветвления False → всё равно PENDING, не REJECTED. Администратор проверяет вручную чеки без акционных товаров. Чек из кафе с продуктами — очевидно не акционный товар, но уходит на ручную проверку.
4 Средний RapidFuzz требует многословный результат (более одного слова в найденном продукте). Короткие названия продуктов могут не проходить фильтр. Если product.name = «Яйцо» (одно слово) — RapidFuzz его отфильтрует.
5 Средний AI-ветвление отключено по умолчанию (ai_mode=False). Смешанные результаты keywords/rapidfuzz не разрешаются автоматически. Keywords=False, RapidFuzz=True → PENDING вместо возможного CONFIRMED через AI.
6 Низкий AI не возвращает конкретные позиции товаров — только True/False. При CONFIRMED через AI поле promo_items останется пустым. В аналитике не будет видно, какой именно товар подтвердил AI.

Предложения

Требует решения
Авто-REJECTED при all_false
Когда все ветвления вернули False — отклонять автоматически вместо ручной проверки. Требует предварительного решения с исключающими ключевыми словами (риск №1), чтобы не отклонять валидные чеки.
Требует решения
Порядок проверки: бренд перед exclude
Если товар уже совпал с product.name — исключающие ключевые слова не должны его блокировать. Нужно уточнить бизнес-правило: исключаются ли акционные товары, содержащие стоп-слово.
Идея
Включить AI для разрешения смешанных результатов
Когда needs_manual_review=True (keywords ≠ rapidfuzz) — автоматически запускать AI-ветвление. Если AI подтверждает → CONFIRMED, если нет → PENDING. Сократит количество чеков на ручную проверку.
Идея
Повторная обработка PENDING-чеков при обновлении ключевых слов
При добавлении новых ключевых слов в БД — запускать переобработку чеков в PENDING через Celery-задачу. Позволит автоматически подтвердить чеки, которые не прошли из-за неполного словаря.
